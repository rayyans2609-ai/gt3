# P3u measurement tools

All commands run from the designated P3u worktree. Each harness checks host admission before opening Chrome, verifies the wrapper's server provenance, closes its own browser, and writes provenance into its result. One browser at a time. Display-sleep prevention is an owned `caffeinate -dimsu` assertion held for the run and SIGTERM-released at exit, whose lifetime is also bound to the harness process (`-w PID`) so even a hard kill cannot leak it; no OS preferences change. Puppeteer's injected `--enable-automation` argument is removed in every run (headful and headless), so the "Chrome is being controlled by automated test software" banner is absent. The runtime value of `navigator.webdriver` is recorded as a fact; removing the argument does not guarantee it is `false`. Headful timing has bounded input acknowledgements and ten-second RAF/visibility watchdogs. Admission failures retry with a twenty-second rest (maximum six checks), never bypassing the host gate. Outputs and Chrome profiles default to git-ignored `local/evidence/p3u/`. Profiles live inside a nested `node_modules/` cache directory so Vite ignores component-created HTML files; otherwise Chrome can provoke an unrelated full-page reload during a measurement. This directory contains browser cache, not installed npm dependencies. Delayed owned startup New Tab pages are closed so they cannot steal the measured tab's foreground state.

The owner reads GT3 in Chrome macOS full screen on the M4 MacBook Air (built-in panel 1470×956 points at 2×, 60 Hz). Headful pacing is measured on that real display path: Chrome launches with `--start-fullscreen`, with CDP `Browser.setWindowBounds` fullscreen as the confirmed fallback (the achieved window state is recorded), and `defaultViewport: null` leaves the real window and device pixel ratio untouched — no emulation. The camera-notch band leaves the true-fullscreen page at 1470×919 @2. Before any timing or capture the harness asserts inside the page that headful `innerWidth`/`innerHeight`/`devicePixelRatio` equal 1470/919/2 (override with `GT3_EXPECT_WIDTH`/`GT3_EXPECT_HEIGHT`/`GT3_EXPECT_DPR`); deterministic emulated captures remain pinned to 1470/956/2 instead. Pointer-nudged rounds first let the fullscreen toolbar settle; geometry that never matches aborts the run with a clear error. The same gate asserts the bottom HUD on-screen: the bounding rectangles of the lap timer (`.hud-lap-timer`), the Day/Night switch (`.theme-segmented`) and the always-visible audio control (`.audio-anchor`) must lie fully inside the viewport, and the music panel (`#music-player`) whenever it is open — closed, it is intentionally transformed out of flow under its anchor, so the anchor stands for it. A violation aborts, and every rectangle is recorded in `report.hudRects`; expected/actual page geometry is in `report.display.geometry`, with physical screen facts alongside in `report.display.screen`.

```sh
GT3_RUN=p3u GT3_TASK=T1 GT3_PORT=5231 \
GT3_SERVER_LOG=local/evidence/p3u/capture-server.log \
GT3_OUT=local/evidence/p3u/locked-a \
scripts/with-verification-server.sh node scripts/p3u-capture.mjs \
  http://127.0.0.1:5231 '?version=locked'

# Repeat with GT3_OUT=.../locked-b, then:
node scripts/p3u-diff.mjs local/evidence/p3u/locked-a \
  local/evidence/p3u/locked-b docs/review/p3u/data/determinism.json

GT3_RUN=p3u GT3_TASK=T1 GT3_PORT=5231 \
GT3_SERVER_LOG=local/evidence/p3u/perf-server.log \
GT3_OUT=local/evidence/p3u/locked-600 GT3_DURATION=600 GT3_TRACE=1 \
scripts/with-verification-server.sh node scripts/p3u-perf.mjs
```

Capture controls: `GT3_STATES=all` (20 car views + grid/gate/finish), `cars`, `key`, or comma-separated state names; `GT3_QUERY` overrides the positional query; `GT3_DEVICE_DPR=2` defaults to Retina PNGs; `GT3_RENDER_DPR=1` defaults to accepted internal render density. Captures keep a viewport-emulated display (fixed CSS viewport 1470×956, default 2×) for deterministic PNGs, but every run still passes the no-banner launch and the same display/HUD on-screen gates as pacing, checked against the pinned emulation. All car states use the accepted Tour rig, model, camera and lighting at route t=.123, placing each car in turn at the same road pose to isolate presentation. They are settled stills, not actual swap midframes. Gate is just before checkpoint 2, with the normal Nissan presentation; finish uses p=1 + the actual V1 run-out distance. Clocks, wheel phase, random seed, parallax, grain and CSS transitions are normalized only for captures. The six-second Sound entry cue is marked seen before bootstrap so named sets cannot differ according to how quickly they reach a state. Manifest contains exact cameras, projected car bounds, material/texture facts, hashes and source/server identity. Capture and diff do not measure pacing.

Pacing controls: `GT3_DURATION=600` seconds (any positive duration; longer runs loop using the real Replay button), `GT3_MODE=tour|steady`, `GT3_THEME=day|night`, `GT3_RENDER_DPR=1|1.5|2`, `GT3_GPU_SCOPE=total|passes|shadow`. Default is **headful** real Chrome/ANGLE Metal on the owner's true fullscreen panel (display and HUD gates above run before timing; `GT3_HEADLESS=1` keeps the emulated viewport for GPU attribution only), with battery saver disabled only in its disposable profile (`GT3_BROWSER_SAVER=1` restores Chromium's below-threshold condition for controls), realistic CDP wheel input every 120 ms with brief releases, four seconds' dwell at each finish, then real Replay. Each report records the measurement conditions: power source and battery percentage (`pmset -g batt`, parsed `powerSource`/`batteryPercent`), Low Power Mode (`pmset -g`), the disposable profile's battery-saver value and meaning, thermal state, document visibility state at start and end of the run, the runtime `navigator.webdriver` fact, and the owned `caffeinate -dimsu` display-sleep assertion with its pid. Each session includes a three-second post-setup warm period. No screenshots during measured windows. `GT3_TRACE=1` records V8 GC trace (optional because tracing can perturb timing). Raw frames, timestamps, inputs, long tasks and GPU values are in `frames.json.gz`; report has overall, per-minute, finish, swap ±500ms, driving and rest distributions. Threshold clusters group bad frames separated by <1s. Segment event rates use sampled segment time, not entire elapsed wall time. Thermal/paging/pressure and process census sample every ten seconds into `host.jsonl`. RAF intervals are vsync cadence, not proof of compositor display; use an owner interaction review for final feel.

GPU scopes deliberately do **not** nest timer queries. `total` times the composer; `passes` samples one enabled pass per frame in round-robin order; `shadow` times only Three's shadowMap.render. Metal sub-pass elapsed readouts proved non-additive; do not sum them or infer exclusive cost by subtraction. Use `scripts/p3u-attrib.mjs` for matched whole-composer ablations at DPR1/1.5/2 (`GT3_DURATION=10` seconds per condition). It also supports offscreen scene-only and scene-without-shadows draws, preserving the original scene program/output target. The ablation delta is the incremental cost of that feature, including interactions, not an isolated GPU-busy hardware counter. A timer query still pending at the end is excluded, and disjoint samples are discarded.

Harness-only candidates: comma-separated `GT3_CANDIDATE=full,aniso,env,msaa2,msaa4,shadow4k,noaa,output,outputwash,carenv`. `full` reroutes existing Tour GLB requests to existing full GLBs before load; `aniso` sets car textures to min(8, device max); `carenv` assigns the same diagnostic map only to car PBR materials (opaque and fade), at .35 Day / .12 Night, leaving the world without IBL; `env` uses Three's built-in RoomEnvironment through PMREM (diagnostic only, not an approved outdoor reflection design); `msaa2` replaces SMAA with 2× on the scene read target (`msaa4` requests 4×); requested and actual samples are recorded. Scene-only MSAA and OutputPass are tested separately because their swap parity differs; `outputwash` instead applies the output transform inside the final wash before its grain/vignette, retaining the two-swap MSAA chain; `shadow4k` doubles the existing shadow map; `output` inserts Three's OutputPass before SMAA to exercise the currently absent tone-mapping/color-transfer stage. Candidate shader variants are warmed for all cars (opaque and fade) outside the timing interval, and the diagnostic warm-up duration is recorded separately from production readiness. Diagnostic browser imports are pre-optimized before app bootstrap to avoid duplicate model residency from a development reload. These modify page handles and requests, never product files. They can be combined. Always label aesthetic candidates for owner review. No profile automatically activates candidates; `?version=unlocked` currently remains the same product rendering as locked.

For the detached reference, use the same wrapper with `GT3_SERVER_ROOT` set to `p3u-ref` and `GT3_PORT=5232`; invoke the harness with an absolute path under this tooling worktree, and use absolute output/log paths under this worktree. Never edit the reference.
